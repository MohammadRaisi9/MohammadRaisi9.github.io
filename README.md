# سایت شخصی و مارکت اپلیکیشن‌های محمد رئیسی

سایت عمومی: https://MohammadRaisi9.github.io/

این مخزن فقط شامل کد عمومی وب‌سایت، اطلاعات عمومی اپلیکیشن‌ها و فایل‌های APK **نهایی و قابل انتشار** است. پروژه خصوصی معلم‌یار و فایل‌های keystore باید خصوصی باقی بمانند.

## پنل مدیریت برنامه‌ها

1. به https://app.pagescms.org/ برو و با حساب GitHub خود وارد شو. مجوز Pages CMS را فقط به مخزن `MohammadRaisi9.github.io` بده.
2. مخزن و شاخه `main` را انتخاب کن. فایل `.pages.yml` آماده است و بخش «اپلیکیشن‌ها» و «تنظیمات سایت و نظرات» را نمایش می‌دهد.
3. هر برنامه را با شناسه انگلیسی یکتا اضافه کن. نام، دسته‌بندی، خلاصه، توضیحات، آیکون، تصاویر گوشی (تا ۱۲ عدد)، امکانات، شماره نسخه و تغییرات را وارد کن.
4. با زدن Save، CMS محتوا را در GitHub ذخیره می‌کند و GitHub Actions سایت را مجدداً منتشر می‌کند. داده‌ها از `content/apps/*.json` در هر انتشار ساخته می‌شوند.

**نکته:** اتصال GitHub به Pages CMS یک مجوز جداگانه است؛ داشتن فایل `.pages.yml` به‌تنهایی ورود به CMS را فعال نمی‌کند.

## بارگذاری APK و دانلود مستقیم

دو مسیر برای APKهای **امضاشده و نهایی** وجود دارد:

- **APK کوچک (زیر ۵۰ مگابایت):** داخل Pages CMS، فایل را در بخش «بارگذاری APK مستقیم» انتخاب کن. فایل در `assets/apks/` ذخیره می‌شود، در نسخه منتشرشده سایت موجود خواهد بود و لینک دانلود آن خودکار ایجاد می‌شود.
- **APK بزرگ:** در GitHub Releases یک مخزن عمومی **مجزا** مثل `android-app-downloads` داشته باش، فایل امضاشده را به Release ضمیمه کن و URL مستقیم فایل (منتهی به `.apk`) را در فیلد `apk_url` وارد کن. برای Release مخزن خصوصی، دانلود عمومی کار نمی‌کند.

بعد از بارگذاری فایل معتبر، `status = released` را انتخاب کن. ساخت سایت عمداً در صورتی که وضعیت «منتشرشده» باشد اما فایل معتبر ارائه نشده باشد **با خطا متوقف می‌شود**؛ در این صورت سایت قبلی بدون تغییر می‌ماند. اگر فایل محلی و URL هر دو موجود باشند، فایل محلی اولویت دارد. تا قبل از انتشار APK واقعی، وضعیت را روی `development` یا `planned` نگه دار. فایل APK را از سورس یا بیلد Debug با کلید امضای متفاوت حدس نمی‌زنیم.

GitHub Pages محدودیت حجم سایت دارد؛ برای APKهای بزرگ، Releases مناسب‌تر است. فایل APK منتشرشده **خودکار نصب نمی‌شود** و نصب نیازمند تأیید کاربر اندروید است.

## نظرات، امتیازدهی و مدیریت آن‌ها

صفحه برنامه فرم نظردهی ایمیلی و نمایش ستاره‌ها را دارد، اما برای فعال شدن به یک پروژه Supabase نیاز دارد:

1. در پروژه Supabase مربوط به وب‌سایت، محتوای `sql/reviews.sql` را اجرا کن تا جدول، محدودیت ثبت یک نظر برای هر کاربر/برنامه و RLS ایجاد شوند. این کار فقط یک‌بار لازم است.
2. در Authentication → Providers، ورود با ایمیل را فعال کن. در Authentication → URL Configuration، آدرس `https://mohammadraisi9.github.io/` را به‌عنوان Site URL و `https://mohammadraisi9.github.io/**` را به Redirect URLs اضافه کن.
3. در Pages CMS → «تنظیمات سایت و نظرات»، **Project URL** و کلید **عمومی** با پیشوند `sb_publishable_` را ذخیره کن. این مقادیر از `content/site.json` در زمان ساخت به فایل عمومی `site-config.js` تبدیل می‌شوند. کلید `sb_secret_`، `service_role`، رمز دیتابیس یا توکن GitHub را هرگز وارد مخزن عمومی نکن.
4. هر نظر بعد از ورود ایمیلی به حالت `pending` ثبت می‌شود. مدیر از Supabase → Table Editor → `app_reviews`، پس از بررسی هر نظر، `status` را به `approved` یا `rejected` تغییر می‌دهد. فقط نظرهای تأییدشده برای دیگران نمایش داده می‌شوند.

برای ترافیک بالا، محافظت CAPTCHA، محدودیت ارسال ایمیل و ابزار گزارش تخلف اضافه کن. اطلاعات نظرات روی سرویس Supabase ذخیره می‌شوند، نه روی گوشی بازدیدکننده.

## توسعه و آزمایش

به Node.js 22 یا جدیدتر نیاز داری:

```bash
node --test tests/site.test.mjs
node scripts/build.mjs
python3 -m http.server 8000 --directory dist
```

با بازکردن `http://localhost:8000` نسخه خروجی را می‌بینی. در GitHub Actions، هر Push به `main` ابتدا تست را اجرا می‌کند و سپس محتوای پوشه `dist` را به Pages می‌فرستد.

**امنیت:** کد منبع خصوصی برنامه‌ها، keystore، credential، دیتابیس خصوصی یا فایل APK آزمایشی را در این مخزن عمومی قرار نده. ثبت نظر از طریق Supabase فقط با RLS محدود می‌شود و نیازمند نظارت مدیر است.
