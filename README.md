# سایت شخصی و مارکت اپلیکیشن‌های محمد رئیسی — نسخه ۲

سایت فارسی و راست‌به‌چپ، مخصوص **محمد رئیسی، معلم و توسعه‌دهنده اندروید با Kotlin**. شامل صفحه شخصی، فهرست اپلیکیشن‌ها، جست‌وجو، صفحه اختصاصی هر برنامه، گالری اسکرین‌شات، دانلود مستقیم APK، نظرات و امتیازدهی پس از ورود با ایمیل، و مدیریت محتوا بدون ویرایش کد با Pages CMS.

## سه بخش و شیوه کار

| بخش | سرویس | توضیح |
|---|---|---|
| سایت عمومی | GitHub Pages | سرو رایگان صفحات HTML/CSS/JS؛ کد خصوصی اپلیکیشن‌ها منتشر نمی‌شود |
| مدیریت برنامه‌ها و تصاویر | [Pages CMS](https://app.pagescms.org/) | با حساب GitHub وارد می‌شوید و عنوان، توضیحات، عکس‌ها، تغییرات و لینک APK را ویرایش می‌کنید. ذخیره = Commit در مخزن = انتشار مجدد خودکار با Actions. |
| فایل نصب APK | GitHub Releases | مخزن عمومی **مجزا** برای فایل‌های خروجی امضاشده؛ نگهداری کد برنامه در آن لازم نیست. |
| نظرات و ستاره‌ها | Supabase | ورود با لینک ایمیل، ثبت یک نظر در هر برنامه، تأیید دستی مدیر، نمایش نظرات تأییدشده. |

**وضعیت تحویل:** سایت و فرم‌های مدیریتی آماده‌اند؛ نمونه‌های معلم‌یار و مربی مطالعه *منتشر نشده‌اند*. دانلود تا آپلود واقعی APK غیرفعال است. بخش نظرات تا ساخت پروژه Supabase، اجرای فایل SQL و واردکردن کلید عمومی فعال نیست. GitHub Pages و Pages CMS نیز نیاز به راه‌اندازی در حساب شما دارند؛ فایل ZIP خودش یک سایت منتشرشده نیست.

## مرحله ۱ — راه‌اندازی سایت روی GitHub

1. یک مخزن عمومی با نام **`MohammadRaisi9.github.io`** در حساب GitHub خود ایجاد کنید. مخزن خصوصی `Moallemyar` را عمومی نکنید.
2. **محتویات این پوشه** (نه فایل ZIP به‌عنوان یک فایل تکی) را در ریشه مخزن جدید Push کنید. نام شاخه `main` باشد.
3. در مخزن جدید به `Settings → Pages → Build and deployment` بروید و `Source = GitHub Actions` را انتخاب کنید.
4. اکشن `.github/workflows/pages.yml` در هر Push، کاتالوگ اپلیکیشن‌ها را از `content/apps/*.json` می‌سازد و پوشه `dist` را منتشر می‌کند.
5. سایت پس از اجرای موفق workflow در `https://MohammadRaisi9.github.io/` نمایش داده خواهد شد. در تب `Actions` نتیجه را ببینید.

## مرحله ۲ — فعال‌کردن پنل ساده مدیریت اپلیکیشن‌ها

1. به [app.pagescms.org](https://app.pagescms.org/) بروید، با GitHub وارد شوید و GitHub App این سرویس را **فقط به مخزن سایت** دسترسی دهید.
2. مخزن `MohammadRaisi9.github.io` را انتخاب کنید. فایل `.pages.yml` در ریشه پوشه از قبل آماده شده است.
3. از بخش **اپلیکیشن‌ها** یک برنامه جدید ایجاد کنید، `id` انگلیسی ثابت و منحصربه‌فرد (مثلاً `my-first-app`) تعیین کنید؛ فایل ساخته‌شده باید `content/apps/my-first-app.json` باشد. اسم و توضیح فارسی، دسته‌بندی، امکانات، آیکون، گالری تا ۱۲ تصویر و اطلاعات نسخه را اضافه کنید.
4. تصاویر در `assets/uploads/` ذخیره می‌شوند؛ استفاده از WebP و عرض مناسب گوشی توصیه می‌شود.
5. بعد از ذخیره در CMS، GitHub Actions به‌طور خودکار سایت را دوباره تولید می‌کند. اگر اولین بار چیزی نمایش داده نشد، تب Actions را بررسی کنید.

> این پنل روی سرویس Pages CMS است و از داخل سایت عمومی یک مسیر مدیریت بدون رمز عبور وجود ندارد. دسترسی مدیریتی همان حساب GitHub مجاز است. اگر مخزن را با نام `website` منتشر می‌کنید، به‌دلیل مسیرهای مطلق عکس‌های خروجی CMS لازم است `.pages.yml` را به مسیر `/website/assets/uploads` تغییر دهید.

## مرحله ۳ — انتشار APK و فعال‌کردن دکمه دانلود

1. مخزن عمومی دیگری مثلاً `MohammadRaisi9/android-app-downloads` برای **فقط خروجی‌های عمومی** بسازید؛ کد و keystore برنامه‌ها را آنجا قرار ندهید.
2. داخل آن Release جدید بسازید؛ برچسب **منحصربه‌فرد هر برنامه و نسخه** مثل `moallemyar-v1.0.0` تعیین کنید و فایل *امضاشده* `moallemyar-v1.0.0.apk` را اضافه کنید.
3. لینک دانلود Asset واقعی را کپی کنید؛ قالب لینک: `https://github.com/MohammadRaisi9/android-app-downloads/releases/download/moallemyar-v1.0.0/moallemyar-v1.0.0.apk` (**مثال؛ تا وقتی آپلود نشده معتبر نیست**).
4. در Pages CMS، `apk_url` را پر کنید، نسخه و حجم را بنویسید و وضعیت را `released` قرار دهید. تا وقتی URL واقعی و پسوند `.apk` نباشد دکمه دانلود فعال نمی‌شود.
5. برای هر نسخه APK فایل Release جدید بسازید و لینک جدید را در CMS جایگزین کنید.

دانلود APK **نصب خودکار نیست**. مرورگر فایل را دریافت می‌کند و کاربر در اندروید باید اجرای نصب و در صورت نیاز مجوز نصب از منبع را تأیید کند.

## مرحله ۴ — فعال‌کردن نظرات و امتیاز کاربران

1. پروژه Supabase جدید بسازید: <https://supabase.com/dashboard>.
2. در بخش `SQL Editor` محتوای `sql/reviews.sql` را اجرا کنید. این SQL جدول `app_reviews`، قواعد Row Level Security و محدودیت «یک نظر به‌ازای هر کاربر و برنامه» را ایجاد می‌کند.
3. در `Authentication → Providers → Email` ورود با ایمیل و Magic Link را فعال نگه دارید. برای سایت عمومی بهتر است SMTP شخصی و محدودیت‌های ارسال ایمیل را تنظیم کنید.
4. در `Authentication → URL Configuration`، آدرس اصلی سایت را `https://MohammadRaisi9.github.io/` و Redirect URL را `https://MohammadRaisi9.github.io/**` اضافه کنید.
5. مقادیر **Project URL** و **publishable key / legacy anon key** را از Supabase در `site-config.js` وارد کنید و تغییر را Push کنید. فقط کلید **عمومی** را در این فایل قرار دهید؛ هرگز `service_role` را در سایت نگذارید.
6. کاربر روی صفحه برنامه با ایمیل لینک ورود دریافت می‌کند، ۱ تا ۵ ستاره و متن نظر را ثبت می‌کند. نظر جدید `pending` است؛ مدیر با `Table Editor → app_reviews` وضعیت نظر بررسی‌شده را به `approved` یا `rejected` تغییر می‌دهد. فقط نظرهای تأییدشده در امتیاز میانگین و فهرست عمومی نمایش داده می‌شوند.

**محدودیت نسخه اول:** ویرایش نظر بعد از ارسال و پاسخ مدیر در صفحه هنوز پیاده‌سازی نشده؛ مدیریت نظر در داشبورد Supabase انجام می‌شود. اگر ترافیک بالا رفت، ضداسپم تکمیلی (Captcha، نرخ‌دهی و سیاست حذف اطلاعات) اضافه کنید. هزینه‌ها و سهمیه سرویس‌ها را پیش از استفاده سنگین بررسی کنید.

## آزمایش محلی

نیاز به Node.js 22 یا جدیدتر:

```bash
node scripts/build.mjs
python3 -m http.server 8000 --directory dist
```

سپس آدرس `http://localhost:8000/` را باز کنید؛ نمونه‌ها، جست‌وجو و صفحات جزئیات بدون Supabase کار می‌کنند. نظرات تنها پس از تکمیل مرحله ۴ و روی آدرس مجاز در Supabase فعال می‌شوند.

## فایل‌های مهم

- `index.html` و `app.html`: صفحه اصلی و صفحه اختصاصی هر اپ
- `styles.css` و `market.css`: سبک تیره نسخه قبلی + طراحی مارکت
- `home.js` و `detail.js`: جست‌وجو، گالری و دریافت داده‌های سایت
- `comments.js` و `sql/reviews.sql`: ورود ایمیلی، نظر و امنیت دیتابیس
- `site-config.js`: فقط پیکربندی عمومی Supabase
- `content/apps/*.json`: برنامه‌ها؛ توسط Pages CMS قابل ویرایش
- `.pages.yml`: تنظیمات پنل مدیریت محتوای سایت
- `scripts/build.mjs` و `.github/workflows/pages.yml`: تولید کاتالوگ و انتشار خودکار

**امنیت:** کد برنامه‌ها، کلید امضا، keystore، توکن‌های شخصی و کلیدهای مدیریتی Supabase را در این مخزن عمومی قرار ندهید. فقط APK نهایی امضاشده منتشر می‌شود. محتوای نظرات به‌صورت متن ساده رندر می‌شود تا HTML کاربران اجرا نشود. هیچ تعداد دانلود یا امتیاز ساختگی در رابط نمایش داده نمی‌شود.
